Node.js Error

ENOENT: no such file or directory

error code: ENOENT

Complete reference — what it means, every cause, and how to fix it.

Quick Answer: Node.js throws Error: ENOENT: no such file or directory when a file system operation targets a path that does not exist. Fix it by verifying the path with path.resolve(), checking process.cwd(), or creating missing directories with fs.mkdirSync(dir, { recursive: true }).

What is ENOENT?

ENOENT stands for Error NO ENTry — a POSIX system error code meaning the named file or directory does not exist. Node.js surfaces it whenever a file system operation — readFile, writeFile, stat, unlink, readdir, rename, and others — cannot find the path you provided.

Exact error messages you will see:
Error: ENOENT: no such file or directory, open '/project/config.json'
Error: ENOENT: no such file or directory, scandir '/project/uploads'
Error: ENOENT: no such file or directory, stat '/project/public/logo.png'

Full Error Example

Error: ENOENT: no such file or directory, open '/project/config.json'
    at Object.openSync (node:fs:596:3)
    at Object.readFileSync (node:fs:464:35)
    at Object.<anonymous> (/project/app.js:3:19) {
  errno: -2,
  code: 'ENOENT',
  syscall: 'open',
  path: '/project/config.json'
}

The error object includes three diagnostic fields:

FieldMeaning
code'ENOENT' — the error type
syscallThe fs operation that failed: open, stat, scandir, unlink, etc.
pathThe exact resolved path Node.js tried to access — use this to debug

Common Causes & Fixes

Cause 1 – Typo in the path

A single wrong character, missing extension, or incorrect directory name produces ENOENT. Always print the resolved path before assuming the file should exist.

const path = require('path');
const fs = require('fs');

const filePath = path.resolve('./conifg.json'); // typo: conifg
console.log(filePath);                          // print to verify before using
const data = fs.readFileSync(filePath, 'utf8');

Cause 2 – Wrong working directory

Relative paths are resolved against process.cwd() — the directory Node.js was launched from, not the location of the source file. Running a script from a different directory changes every relative path. 

// Diagnose
console.log('cwd:', process.cwd());
console.log('resolved:', path.resolve('./config.json'));

// Fix: use __dirname to anchor paths to the source file's location
const filePath = path.join(__dirname, 'config.json');

Cause 3 – Intermediate directory doesn't exist

Writing a file to ./output/reports/summary.csv fails if output/ or output/reports/ do not exist yet. Create the full directory tree before writing. 

const fs = require('fs');
const path = require('path');

const outputDir = path.join(__dirname, 'output', 'reports');
fs.mkdirSync(outputDir, { recursive: true }); // creates all missing dirs
fs.writeFileSync(path.join(outputDir, 'summary.csv'), data);

Cause 4 – Async race condition

Reading a file immediately after triggering an async operation that creates it can fail if the write hasn't finished yet. Always await the write before reading. 

// Wrong – read may run before write completes
fs.writeFile('./data.json', content, () => {});
const result = fs.readFileSync('./data.json'); // ENOENT possible

// Correct – await the write
await fs.promises.writeFile('./data.json', content);
const result = await fs.promises.readFile('./data.json', 'utf8');

Cause 5 – Case sensitivity on Linux

macOS and Windows are case-insensitive — Config.json and config.json are the same file. Linux (including most CI/CD and production servers) is case-sensitive. Code that works locally can throw ENOENT in production. 

// Wrong on Linux (file on disk is config.json)
const data = fs.readFileSync('./Config.json');

// Correct – match the filename exactly
const data = fs.readFileSync('./config.json');

Cause 6 – Hardcoded absolute paths

Absolute paths like /home/alice/project/data.csv only work on one machine. Use __dirname or environment variables to make paths portable. 

// Wrong – breaks on every other machine or in Docker
const data = fs.readFileSync('/home/alice/project/data.csv');

// Correct
const data = fs.readFileSync(path.join(__dirname, 'data.csv'));

Safe File Access Patterns

Check before reading

if (fs.existsSync(filePath)) {
  const data = fs.readFileSync(filePath, 'utf8');
} else {
  console.warn('File not found:', filePath);
}

Handle the error gracefully with try/catch

try {
  const data = await fs.promises.readFile(filePath, 'utf8');
} catch (err) {
  if (err.code === 'ENOENT') {
    console.error('File not found:', err.path);
  } else {
    throw err; // re-throw unexpected errors
  }
}

Ensure directory exists before writing

async function writeFileSafe(filePath, content) {
  await fs.promises.mkdir(path.dirname(filePath), { recursive: true });
  await fs.promises.writeFile(filePath, content);
}

Debugging Checklist

  1. Read err.path from the error object — it shows the exact path Node.js tried.
  2. Print process.cwd() to confirm the working directory at runtime.
  3. Print path.resolve('./your/path') to see the absolute path before using it.
  4. Check err.syscall to know which fs operation failed.
  5. Verify the file exists on disk and that the case matches exactly.
  6. In Docker/CI, confirm the file is actually copied into the container/workspace.
Common mistake: Using fs.existsSync() as a guard and then calling fs.readFileSync() is still vulnerable to a race condition in concurrent code — another process can delete the file between the two calls. Prefer try/catch with err.code === 'ENOENT'.

Related Errors

  • EACCES: permission denied — the path exists but the process lacks read/write permission
  • ENOTDIR: not a directory — a path component exists as a file, not a directory
  • EEXIST: file already exists — thrown by exclusive create operations when the path already exists
  • MODULE_NOT_FOUND — similar "not found" error but from the module loader, not the fs module
